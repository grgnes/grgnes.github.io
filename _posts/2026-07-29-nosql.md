## Introduction

NoSQL Injection is a web security vulnerability that allows an attacker to manipulate NoSQL database queries. It usually occurs when user input is included in database queries without proper validation, allowing attackers to bypass authentication, access sensitive data, or modify database records.

## Labs

### 01. Detecting NoSQL injection

I used the normal category filter. The application worked as expected. This was my baseline request.

- Injection

```bash
Gifts 
```

I added a single quote (`'`) to the category value. The server returned a syntax error. This showed that the input was processed as JavaScript.

- Injection

```bash

```

<img src="/assets/posts/nosql/image (1).png" width="700" >

I added another single quote to create a valid JavaScript expression. The query worked again without an error.

- Injection

```bash
Gifts'+'
```

<img src="/assets/posts/nosql/image (2).png" width="700" >

I used the `' && 0 && 'x` payload. The condition was **false**, so no products were returned.

- Injection

```bash

```

<img src="/assets/posts/nosql/image (3).png" width="700" >

I sent the `' && 1 && 'x` payload. The condition was **true**, so the products were displayed again.

- Injection

```bash
Gifts' && 1 && 'x 
```

<img src="/assets/posts/nosql/image (4).png" width="700" >

I used the `'||1||'` payload. The expression was always **true**, so hidden products were displayed. This confirmed the NoSQL Injection vulnerability.

